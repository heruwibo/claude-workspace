# McKinsey-style slide deck

Style inspired by the publicly visible conventions of strategy-firm decks. Do not use any firm's logo or trademarks; the look is emulated, not branded.

## Storyline
- Answer first (Pyramid Principle): the executive summary states the recommendation, then supports it with 3 MECE arguments.
- Read only the slide titles in sequence: they must tell the whole story.
- Typical flow: Executive summary → Context/problem → Analysis (2–4 sections) → Recommendation → Roadmap/next steps → Appendix.

## Slide anatomy
- **Action title**: a full sentence, max 2 lines, stating the "so what" (e.g. "Cutting procurement spend by 12% is achievable within 18 months"). Never a topic label like "Procurement overview".
- Body: one chart, table or framework supporting exactly one message.
- Tracker/section marker top-right or top-left (small), optional.
- Footer: "Source:" line and notes in small grey text (8–10 pt); slide number bottom-right.
- Callout: a single highlighted box or bracket pointing to the takeaway.

## Visual language
- White background; deep navy (~#051C2C) for titles, one bright blue/cyan accent (~#2251FF / #00A9F4), greys for everything else.
- Serif-free, clean sans (Arial/Helvetica-like; Georgia sometimes for titles). Title 24–28 pt, body 12–16 pt, never below 10 pt except footnotes.
- Thin rules, no gradients, no shadows, no clip-art. Generous whitespace.
- Charts: direct data labels, no gridlines or legends where labelling is possible; highlight the key bar/series in the accent color and grey the rest; waterfall, stacked-bar and 2x2 matrices are staples.
- Frameworks: issue trees, 2x2s, Gantt/roadmaps, harvey balls for assessments.

## Rules of thumb
- One message per slide; if the title needs "and", split it.
- Every number has a unit, period and source.
- Max ~5 bullets, ideally none: prefer structured visuals.
- Exec summary: 1 slide, bold lead-in phrases followed by one supporting sentence.

## Workflow
1. Ask for or infer the core question, audience and decision needed.
2. Draft the storyline as a list of action titles; confirm if unclear.
3. Build slides (use the pptx skill for .pptx output), then check: titles read as a story, one message per slide, sources present.
